# Review of v3.2.5 — 2026-11-17

Base: `xemadx/spoof-tunnel`, `origin/main` commit `b8115af` (latest GitHub
release checked: `v3.2.5`). Changes are on the local branch
`fix/review-v3.2.5`. Local Linux builds are stamped `v3.2.6-dev`; this is
not a published release.

## Corrected behavior

1. **Active one-way TCP sessions no longer expire as idle.** Previously each
   direction had its own read deadline, so a continuous download could be cut
   off after five minutes without new client request bytes. Traffic now refreshes
   the connection's shared inactivity deadline. The bounded half-close drain
   remains in effect. Short writes close the pipe instead of silently losing data.
2. **The forwarding connection cap includes pending target connections.** Counting
   socket handles and dividing by two undercounted clients still waiting for a
   target. Each accepted pipe now reserves one slot until its worker exits.
3. **Lost source manifests can restart with the same request token.** An entirely
   lost or discarded transfer previously caused repeated requests to be ignored
   until the sender's transfer expired. Repeated requests now rebuild the
   transfer, with the existing one-second request rate limit retained.
4. **Closing a raw socket waits for active senders.** An atomic closed flag alone
   did not protect the descriptor between checking the flag and `Sendto`;
   another socket could reuse that descriptor. A read/write lifecycle lock lets
   sends run concurrently while serializing descriptor destruction.
5. **ICMP suppression no longer drops every ordinary ping reply.** Suppression
   matches the configured ICMP identifier, including the diagnostic tester's
   `0x5354`, instead of relying on a `sp+` interface-name exclusion. Missing
   `u32` support remains a logged best-effort suppression failure. There is no
   blanket UDP port-unreachable fallback that affects unrelated services.
6. **Firewall rules have independent ownership and reliable stale cleanup.**
   Receiver instances in the same process use unique rule comments. Stopping
   one does not remove another's rule. Cleanup strips the quotes printed by
   `iptables -S` before passing comments to `exec`, and rule operations wait
   for the xtables lock.
7. **Concurrent integration runs use different veth names.** Carrier and delay
   tests previously used fixed host-side interface names; simultaneous runs
   could fail before any tunnel started. Names now include the process ID.

The ICMP offset expression follows the upstream
[Netfilter u32 documentation](https://www.iptables.org/documentation/HOWTO/netfilter-extensions-HOWTO-3.html)
and was exercised with actual iptables and ping in an isolated namespace.

## Reproduction and regression coverage

Before the fixes, new tests failed with:

- `TestOneWayTrafficKeepsPipeAlive`: active download ended after 8 of 20 bytes.
- `TestConnectionLimitIncludesPendingTargets`: the excess client timed out
  instead of being rejected while the first target was pending.
- `TestManifestRequestRetriesLostInitialTransfer`: repeated request produced
  no new chunk.

All three pass after the fixes. Additional regressions verify descriptor
lifetime, idle expiration, bounded half-close, ordinary ICMP reachability,
independent suppression ownership and stale-rule cleanup. The firewall test
only runs with `SPOOF_BACKSCATTER_ISOLATED=1` inside the namespace created by
`scripts/integration_backscatter.py`. Its diagnostics-workflow invocation is
prepared locally; publishing that workflow edit requires the GitHub OAuth
`workflow` scope, which the current login does not have. The script was run
successfully locally as recorded below.
