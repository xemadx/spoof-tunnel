# Smart source pools

Upgrade both panel/core pairs before enabling smart dispatch. Existing tunnels retain `legacy` packet rotation. Open the source-pools tab, import newline-separated IPv4 TXT files, select files and their order, stop this connection, apply, then start both ends. Uploads are staged, not automatically activated; overlapping file membership never increases an address weight. A permanent manual `default` group stores pasted IPv4 addresses; every uploaded TXT is a distinct `file` group with its filename. The default group cannot be deleted. Upgrade migration preserves the old inline pool or single source in the default group, without duplicating existing named-file sets. At least one non-empty group must remain selected.

Iran transmit uses successful Iran-to-outside sources; the foreign transmit side uses successful outside-to-Iran sources. The opposite receiver must admit the full selected transmit set. Enable automatic peer sync on both ends, or explicitly request the peer manifest while both updated engines run.

Modes: `adaptive` selects a verified source by smoothed RTT and non-response score with switching hysteresis; `round_robin` rotates verified data sources without control traffic consuming their turns; `failover` pins the current usable source until failure, then selects in configured file/IP priority. `legacy` preserves old behavior without quality enforcement.

Probes use the connection's real peer destination and carrier/ports. AEAD acknowledgements bind unpredictable tokens to the source actually observed by the receiver. Initial admission requires two consecutive successful probes, alternating small and configured-MTU-sized frames. RTT is round-trip, not one-way latency or Internet throughput. Probe deadlines adapt to authenticated RTT; an unmeasured path starts with a 15-second allowance, and measured paths use at least 3 seconds with latency headroom (bounded at 60 seconds). Three consecutive reference-qualified timeouts, or at least three misses in a recent six-observation window with sufficient samples, quarantine the source for 600 seconds. A stale reverse/control path does not establish source-specific failure. Expiry only enables a rate-limited retest, never automatic promotion.

The per-link controller defaults to 25 packets/second, configurable 1–100, with at most 128 pending probes and no per-source goroutines. It does not rate-limit data or the existing heartbeat. Discovery is progressive; a 122k-source inventory has no instantaneous full quality result. Source quality does not prove application-proxy health, future allowlisting, or provider acceptance.

Peer manifests are sorted IPv4 snapshots, compressed, chunked and repaired with bounded retransmission requests. Authentication is the existing directional AEAD, not the public `EMC1` demultiplexing hint. The hint prevents another link's busy raw carrier from exhausting unknown-source control admission. Unknown sources can only attempt bounded authenticated pool control; data still requires an admitted source. Digest, request nonce, address validity and disjointness are verified before atomically replacing the allowlist. No panel token, password or PSK is exchanged through the peer API. Automatic mode waits for peer acknowledgement of its transmit manifest before sending application data.

The private per-link checkpoint binds quarantine deadlines and learned peer sources to the PSK identity, endpoints and carrier/port tuple. Restarts preserve valid quarantine deadlines but require fresh quality verification. A restart can re-confirm a peer's already admitted manifest without requiring a concurrent remote restart. Storage failures are visible. Configuration changes remain stopped-link operations; this release does not promise zero-downtime pool reconfiguration or connectivity without any traversable path.

Limits: 64 named TXT files plus the default group, 262,144 selected unique sources per connection, 10 MiB UI TXT uploads, plain IPv4 lines only. Settings send file IDs, not massive inline lists; general-editor and periodic responses omit large pools. Telemetry is paginated to 50 rows by default, 100 maximum. Legacy endpoints cannot silently overwrite file-managed sets.

Validation: scheduler fake-clock quarantine/recovery and reverse-path ambiguity; MTU-only failures; control/data rotation fairness; 122,437-source compressed manifest; a 260k-row two-file API import reduced to 200k unique sources; authenticated raw tests across all five carriers; source-specific packet-drop injection/checkpoint; isolated TUN TCP/UDP transfer, asymmetric carriers and one-sided process restart; browser/mobile/RTL regressions. See the test suite and `SPOOF_SMART_POOL=1 python3 scripts/integration_l3.py`.

New TUN pairs default to adaptive selection and automatic peer synchronization; upgrade migrations leave existing policy unchanged.

Active/control sources receive reserved probe slots ahead of bulk discovery. Quality without a recent verification expires to unknown and must be rechecked; it is not a permanent healthy label. Authenticated readiness from the other engine is required before smart data dispatch and connected telemetry.

In v0.4.1, pending default content and the checked group/policy selection save atomically through either save button. An empty default is removed from the selected set; at least one nonempty group is required. Invalid requests preserve the previous contents and selection. Per-source reason codes and bounded aggregate pool logs explain unknown reverse paths, timeout/quarantine and stale verification. Ineligible sources are omitted from active-source telemetry.
