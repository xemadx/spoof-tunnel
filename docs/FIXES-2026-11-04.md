# v0.3.6 reliability corrections

## Process supervision and route confinement

The manager retains explicit runtime intent separately from the boot Enabled flag. Unexpected process exits close all forwarders and schedule recovery after 1, 2, 4, 8, 16 and at most 30 seconds. Thirty seconds of stable execution resets the failure streak. Explicit Stop, Restart, deletion and shutdown invalidate queued attempts through an epoch and cancellation channel. A fast exit during recovery cannot lose the next retry. Failures and retry delays are logged. Bounded per-instance crash history survives automatic recovery, and retry messages reach the live log subscribers. Forward target sockets are bound to their specific TUN device; missing TUNs cannot fall back to another route. Successful dials clear stale dial errors.

## Packet sizing and diagnostics

The Linux kernel still performs normal interface MTU handling. Additional inner IPv4 validation records invalid packets in both directions. Oversized non-DF packets can be fragmented, preserving offsets, MF and IPv4 copied-option semantics. Oversized DF packets generate an ICMP type 3/code 4 response with the configured next-hop MTU; error replies are suppressed for non-first fragments, multicast/global broadcast and ICMP errors. The TUN address is used as the ICMP source. Outer-path/provider limitations still require deployment testing.

Counters distinguish local drops, invalid inner packets, MTU rejects, authenticated timestamp rejects, and source-filter ignores. The most recently ignored source is exported and source-filter logs are rate-limited. Source ignores can be traffic for another link and are not measured path loss. Telemetry parsing no longer depends on JSON property order; the event prefix remains compatible with older panels.

## Clock errors

AEAD authentication is checked before reporting a timestamp error. An unauthenticated modified frame cannot trigger the clock diagnostic. The existing acceptance window and replay checks are unchanged. The panel exposes an authenticated frame's clock offset and cumulative time rejects; valid traffic clears the active warning. No system clock is changed automatically. Delayed/replayed authenticated traffic can also be outside the timestamp window, so the message does not assert NTP is always the cause.

## Correlated tester probes

Both panels must be upgraded. Each new receiver run generates a random 128-bit code unless the administrator explicitly supplies a code. The sender requires that same 32-character hexadecimal code. ICMP and TCP SYN probes carry a version marker, sequence and source-bound HMAC-SHA256 authenticating the sequence and declared packet count. Ordinary traffic, wrong-run payloads, changed sources and out-of-range sequences and packet-count mismatches are rejected. Per-source bitmaps count each sequence only once. A replay from a prior run is rejected with a fresh code. Manually reusing a code intentionally forfeits cross-run isolation; use a fresh code for every run. This probe format is intentionally incompatible with legacy tester packets. The tunnel wire format is unchanged.

## Validation

Race-enabled Go tests cover crash recovery, cancellation during backoff, reordered telemetry, trusted versus untrusted clock diagnostics, packet fragmentation and ICMP checksums. A loopback-only namespace verifies unique ICMP/TCP delivery and rejects repeated, unrelated and wrong-code packets. Real multi-peer tests kill one owned core process and verify automatic recovery and uninterrupted neighbouring links on all five carriers. An asymmetric 1300/1000 MTU test verifies 2000-byte UDP round trips and authenticated carriage of an ICMP fragmentation-needed response. Seventeen browser tests cover the shared-code workflow and existing UI behaviour. CI gates release publication on the full carrier matrix and these regressions.
